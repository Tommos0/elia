## How this part fits together

`Elia.LLM` dispatches provider-neutral requests and manages the selected provider/model. `Anthropic` implements its own message and SSE conversion; OpenRouter and llama.cpp share `OpenAI` encoding. `Retry` separates idle-stream timeout/transport retry policy from the loop's step retry schedule. Provider-tagged raw reasoning blocks are retained so a provider can receive its own protocol data back without sending another provider's opaque blocks. [Dispatcher](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm.ex), [shared adapter](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/openai.ex), [Anthropic](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/anthropic.ex), [retry policy](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/retry.ex).

Compaction keeps the saved transcript and derives a smaller request view. Its state records elided items, covered/folded boundaries, a summary, exact ledger entries, pins and options. It preserves tool-call/result pair relationships and has explicit migration handling for older compaction shapes. Token counts are intentionally inexpensive estimates, calibrated against available provider usage; they are not exact tokenizer measurements. This separation is a sound foundation and should survive the lifecycle fix below. [Compaction state and migration](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/compaction.ex#L19-L52), [legacy materialization](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/compaction.ex#L217-L281), [token estimator](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/tokens.ex), [usage calibration](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/context.ex).

## LLM-01 — Move slow summarization out of the session callback

### Source chain

1. `Agent.send_message/2`, `Agent.compact/1`, `snapshot/1` and `stop/1` use synchronous `GenServer.call` without an explicit timeout. The normal default is five seconds. [Public calls](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/agent.ex#L77-L83), [Stop](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/agent.ex#L190-L191), [Compact](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/agent.ex#L268-L274), [Elixir call contract](https://github.com/elixir-lang/elixir/blob/v1.17.3/lib/elixir/lib/gen_server.ex#L1103-L1117).
2. `Session.handle_call(:compact, ...)` runs compaction before replying. Starting a turn also calls `compact_at_turn_start/1` before spawning the separate loop task. [Manual callback](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/agent/session.ex#L291-L299), [turn-start decision](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/agent/session.ex#L953-L978), [start_turn](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/agent/session.ex#L1198-L1250).
3. When the cold history is nonempty and a summary is required, `Compaction.fold/4` invokes the summarizer inline. The default summarizer directly calls `LLM.stream/2`. A provider request therefore executes inside the session process. [Fold and summarizer](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/compaction.ex#L859-L903).
4. The chat/settings LiveViews call these APIs directly from event handlers. They neither offload the request nor catch a call timeout. [Send/compact handlers](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia_web/live/chat_live.ex#L1557-L1610), [settings compact handler](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia_web/live/chat_settings_live.ex#L1023-L1036).

### Trigger and consequence

Use a chat with aged-out history that needs a summary; invoke Compact now or cross the automatic turn-start threshold; let summarization take more than five seconds. The caller can time out and its LiveView can exit/reconnect, while the session continues the provider request. During that request, Stop and snapshot calls queue behind it and can time out too. The session may later finish compaction and start the requested turn after the original caller has already failed. A queued Stop may eventually execute; the defect is the blocked control surface and inconsistent acknowledgment, not proof that Stop is lost forever.

A 90-second provider idle timeout is not a five-second response guarantee, and a stream that continues receiving bytes can run longer. The mid-turn compaction path explicitly avoids summarization, so this finding is restricted to manual and turn-start folds. [Idle timeout policy](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/retry.ex#L30-L44), [mid-turn rule](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/compaction.ex#L504-L526).

### Existing coverage, repair, and acceptance

The compaction tests exercise pruning, incremental folding and failure fallback using fast injected summarizers. The LiveView test for Compact now verifies the ordinary interaction. Those do not establish responsiveness while a summarizer is held. [Compaction tests](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/test/elia/llm/compaction_test.exs#L487-L603), [UI test](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/test/elia_web/live/compaction_test.exs#L328-L359).

Define a compacting/preparing operation owned by the session but executed in a monitored worker. Reply promptly, keep Stop/snapshot responsive, and apply the result only if its chat generation/turn identity is still current. State whether a concurrent send queues or returns busy. Retain the pruned-view fallback on summary failure. Simply increasing the call timeout leaves the session unresponsive and should not be the complete fix.

Use a deterministic held summarizer: it announces entry and waits for a test message. While held, assert that the initiating LiveView remains alive, state is visible, and Stop promptly cancels the pending operation. Release a cancelled worker and prove its late result cannot start a turn or overwrite newer state. Cover manual compaction, automatic turn-start compaction, provider failure, session death, and two rapid sends. Coordinate with CORE-02 and CORE-04 because all touch session ownership/persistence. Owning contracts: COMPACT-5/6/10/17/20, SESS and stop behavior. Add an explicit responsiveness/cancellation requirement through the repository's spec-approval workflow.

## LLM-02 — Handle symbolic or malformed stream error codes without raising

`OpenAI.error_code/1` accepts a binary code and immediately takes element zero of `Integer.parse(code)`. A nonnumeric string returns `:error`, which is not a tuple, so the parser raises. This path is reached by an HTTP-200 SSE chunk containing an error map. An example fixture is `{"error":{"code":"model_loading","message":"Model unavailable"}}`. The message is available, but code extraction prevents returning it through the adapter's error contract. [Chunk error path](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/openai.ex#L283-L300), [code parser and finish](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/openai.ex#L389-L408).

**Qualification:** the review does not assert that the configured remote providers currently emit this exact fixture. It is a concrete robustness hole for a malformed or symbolic error code received by the shared OpenAI-compatible stream handler. It affects the provider boundary and can turn an intelligible service error into a generic crashed step. Existing OpenRouter/local-server tests cover numeric error codes, including 502, 400 and 503. [OpenRouter tests](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/test/elia/llm/open_router_test.exs#L341-L360), [local-server test](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/test/elia/llm/llama_cpp_test.exs#L274-L285).

Pattern-match the parse result, treat unknown codes as unknown, and preserve the provider's message. Decide explicitly whether numeric prefixes such as `"503junk"` count; accepting only a complete numeric string is easier to reason about. Test integer and string numeric codes, arbitrary/empty strings, absent/null codes, and unexpected types. Require the correct transient/permanent classification and no raised exception. Do not widen retry eligibility merely because a code could not be parsed. Relevant contracts: LLM-22/23/36 and LOCAL-10; no persisted shape change is needed.

## Limits of this track and focused next checks

The provider-neutral architecture, raw block preservation, incremental SSE parsing, idle-timeout tests over a real socket, and fake-provider fixtures are good foundations. This review did not exercise a live Anthropic/OpenRouter/llama.cpp server, compare current vendor API documentation, measure pricing accuracy, or run the full compaction property space. Model IDs, beta headers and pricing tables are time-sensitive integration data; validate them with provider-owned sources and a controlled integration check before claiming current compatibility. [Provider source/config](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/lib/elia/llm/anthropic.ex#L25-L61), [real-socket test source](https://github.com/Tommos0/elia/blob/5be0bd873bd2716529de25541efb1825495cd12e/test/elia/llm/stream_timeout_test.exs).

Follow up on clean EOF before a protocol finish marker, malformed SSE field shapes, bounding a very large single data event, and cancellation during summarization. These are explicit validation questions, not additional established findings. Preserve the existing distinction between provider retries before streamed data and the loop's own retry/reset handling.
